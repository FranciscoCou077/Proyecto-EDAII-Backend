	\section{Módulo de Algoritmos}
	
	La carpeta \texttt{algoritmos} contiene las implementaciones principales de estructuras de datos, algoritmos de búsqueda, ordenamiento, grafos, manejo de archivos y procesamiento paralelo. Su función dentro del sistema es concentrar la lógica computacional que posteriormente puede ser utilizada por la API y representada visualmente en el front-end.
	
	Este módulo no está diseñado para mostrarse directamente al usuario final, sino para proporcionar las operaciones que serán consumidas desde la interfaz. Por ello, la documentación se enfoca en describir brevemente qué hace cada archivo y cómo podría representarse en la parte visual del sistema.
	
	% -------------------------------------------------
	\subsection{Carpeta \texttt{arboles}}
	
	La carpeta \texttt{arboles} contiene algoritmos relacionados con estructuras jerárquicas y conversión de expresiones matemáticas. Incluye árboles binarios, árboles B, árboles B+ y conversión entre notaciones infija, prefija y sufija.
	
	\begin{table}[H]
		\centering
		\begin{tabular}{|p{4cm}|p{5cm}|p{5cm}|}
			\hline
			\textbf{Archivo} & \textbf{Descripción breve} & \textbf{Uso en front-end} \\
			\hline
			\texttt{binary\_tree.py} & Implementa un árbol binario de búsqueda con inserción, búsqueda, eliminación y recorridos. & Permite visualizar un árbol, mostrar recorridos como inorden, preorden, postorden y nivel-orden. \\
			\hline
			\texttt{btree.py} & Implementa un Árbol B de orden 3, útil para almacenar claves en nodos con varios hijos. & Puede mostrarse como una estructura por niveles, representando cada nodo como una caja con claves. \\
			\hline
			\texttt{bplustree.py} & Implementa un Árbol B+ donde los datos se almacenan en hojas enlazadas. & Puede visualizarse mostrando hojas conectadas y valores ordenados secuencialmente. \\
			\hline
			\texttt{notation.py} & Convierte expresiones infijas a notación sufija o prefija. & Puede usarse en una vista donde el usuario escriba una expresión y vea la conversión. \\
			\hline
			\texttt{router.py} & Expone endpoints para trabajar con árboles y notaciones. & Permite que el front-end mande datos y reciba resultados en formato JSON. \\
			\hline
		\end{tabular}
		\caption{Resumen de archivos de la carpeta arboles}
	\end{table}
	
	En la interfaz, esta sección puede funcionar como un visualizador de árboles. El usuario ingresaría valores, seleccionaría el tipo de árbol u operación, y el sistema mostraría el resultado mediante recorridos, estructuras por niveles o conversiones de expresiones.

	La carpeta \texttt{archivos} contiene funciones para guardar archivos en el backend y consultar información básica de ellos.

		\begin{tabular}{|p{4cm}|p{5cm}|p{5cm}|}

	\subsection{Carpeta \texttt{busqueda}}
	
	La carpeta \texttt{busqueda} contiene algoritmos para localizar un valor dentro de un arreglo.
	
	\begin{table}[H]
		\centering
		\begin{tabular}{|p{4cm}|p{5cm}|p{5cm}|}
			\hline
			\textbf{Archivo} & \textbf{Descripción breve} & \textbf{Uso en front-end} \\
			\hline
			\texttt{busqueda\_lineal.py} & Recorre el arreglo elemento por elemento hasta encontrar el valor objetivo. & Puede mostrarse como una búsqueda paso a paso resaltando cada comparación. \\
			\hline

			\hline

	La carpeta \texttt{ordenamiento} contiene algoritmos para ordenar arreglos numéricos. Algunos de ellos registran pasos intermedios, lo cual permite crear animaciones o visualizaciones didácticas.
	
	\begin{table}[H]
		\centering
		\begin{tabular}{|p{5cm}|p{5cm}|p{5cm}|}
			\hline
			\textbf{Archivo} & \textbf{Descripción breve} & \textbf{Uso en front-end} \\
			\hline
			\texttt{sorting\_algorithms.py} & Implementa Bubble Sort, Heap Sort y Quick Sort con pasos intermedios. & Permite animar comparaciones, intercambios y pivotes. \\
			\hline

	\section{Integración General con Front-End}
	
	La integración visual del módulo \texttt{algoritmos} se basa en permitir que el usuario interactúe con cada algoritmo mediante formularios y componentes gráficos. El front-end no debe implementar directamente la lógica interna de los algoritmos, sino enviar los datos al backend y mostrar los resultados recibidos.
	
	De forma general, el flujo sería:
	
	\begin{enumerate}
		\item El usuario ingresa datos desde la interfaz.
		\item El front-end valida la información básica.
		\item Se envía una petición al backend.
		\item El backend ejecuta el algoritmo correspondiente.
		\item El resultado se devuelve en formato JSON.
		\item El front-end muestra el resultado de forma visual.
	\end{enumerate}
	
	Cada módulo puede tener una representación visual diferente:
	
	\begin{itemize}
		\item \textbf{Árboles}: nodos conectados, recorridos y niveles.
		\item \textbf{Archivos}: carga de archivos y tarjetas con metadatos.
		\item \textbf{Búsqueda}: arreglo con elementos resaltados durante la búsqueda.
		\item \textbf{Grafos}: nodos, aristas y recorridos BFS/DFS.
		\item \textbf{Ordenamiento}: barras animadas, comparaciones e intercambios.
		\item \textbf{Paralelos}: gráficas de tiempo, speedup y eficiencia.
	\end{itemize}
	
	Esta integración permite que la documentación no solo explique el código, sino que también sirva como guía para que el equipo de front-end implemente las vistas correspondientes.
